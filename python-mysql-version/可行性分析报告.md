## 四、MySQL 的引入方案

### 4.1 MySQL 在项目中的定位

任务书明确数据存储在 4 个文本数据源中，头歌平台评测也是基于文本文件。因此 **MySQL 的定位是"本地增强存储层"，而不是替代核心算法**：

```
[原始 txt 数据] ──导入脚本──> [MySQL 数据库] ──Python 读取──> [内存数据结构] ──算法──> [输出]
```

- **导入**：写 `import_data.py`，用 pymysql 将 stocks.txt / entity.txt / relation.txt / detail/*.txt 批量导入 MySQL。
- **核心算法仍然用 Python 手写数据结构**（BST、Trie、Hash、链表、并查集、堆、归并、决策树、邻接表、KNN 等），保证"数据结构课程设计"的考核点不丢失——**如果用 SQL 完成查找/排序就失去课程意义**。
- **导出**：写 `export_data.py`，从 MySQL 导出回 txt 格式（供头歌评测或答辩演示）。

### 4.2 数据库表设计建议

```sql
CREATE DATABASE IF NOT EXISTS stock_system DEFAULT CHARSET utf8mb4;

-- 股票基本信息表（对应 stocks.txt，300 行）
CREATE TABLE stocks (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  stock_code    VARCHAR(20)  NOT NULL UNIQUE,   -- 股票代码 cn_600519
  stock_name    VARCHAR(50)  NOT NULL,          -- 股票简称
  en_name       VARCHAR(100),                   -- 英文名
  industry_code VARCHAR(20),                    -- 行业编码
  industry_l1   VARCHAR(50),                    -- 一级分类
  industry_l2   VARCHAR(100),                   -- 二级分类
  exchange      VARCHAR(50),                    -- 上市交易所
  company_name  VARCHAR(100),                   -- 公司全称（机构名称）
  launch_date   VARCHAR(20),                    -- 上市日期
  province      VARCHAR(50),                    -- 省份
  city          VARCHAR(50),                    -- 城市
  legal_person  VARCHAR(50),                    -- 法人
  address       VARCHAR(200),                   -- 地址
  url           VARCHAR(300),                   -- 网址
  email         VARCHAR(200),                   -- 邮箱
  phone         VARCHAR(50),                    -- 电话
  main_business VARCHAR(700),                   -- 主营业务
  business_scope VARCHAR(700)                   -- 经营范围
);

-- 每日行情表（对应 detail/*.txt，300 支 × 若干天）
CREATE TABLE stock_daily (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  stock_code    VARCHAR(20) NOT NULL,
  trade_date    VARCHAR(20) NOT NULL,           -- 日期
  open_price    DOUBLE,      -- 开盘价
  close_price   DOUBLE,      -- 收盘价
  highest       DOUBLE,      -- 最高价
  lowest        DOUBLE,      -- 最低价
  volume        DOUBLE,      -- 成交量
  turnover      DOUBLE,      -- 成交额
  change_rate   VARCHAR(20), -- 换手率
  rise_fall_rate VARCHAR(20),-- 涨跌幅
  rise_fall_amount DOUBLE,   -- 涨跌额
  UNIQUE KEY uk_code_date (stock_code, trade_date)
);

-- 实体表（对应 entity.txt，1338 行）
CREATE TABLE entities (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  entity_name VARCHAR(300) NOT NULL,            -- 实体内容
  entity_type VARCHAR(50)  NOT NULL             -- 实体类别（10 种之一）
);

-- 三元组表（对应 relation.txt，2700 行）
CREATE TABLE relations (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  head_entity VARCHAR(300) NOT NULL,            -- 头实体
  relation    VARCHAR(50)  NOT NULL,            -- 关系（9 种之一）
  tail_entity VARCHAR(300) NOT NULL             -- 尾实体
);
```

**表设计要点**：
- `utf8mb4` 字符集（避免中文 + emoji 问题）；任务书提醒的 GBK/UTF-8 差异在 MySQL 统一用 `utf8mb4` 后彻底消除。
- 唯一键防重，便于重复导入。
- 300 支 × 每支约 5 天 = 约 1500 行情行，规模极小，无需分表。

### 4.3 与头歌评测的兼容策略

| 场景 | 处理方式 |
|---|---|
| 本地开发/答辩 | 优先读 MySQL（体现数据库能力），算法从 MySQL 取数到内存结构 |

## 五、风险与注意事项

1. **MySQL 凭据**：MySQL80 服务运行中，但 root 密码未知。需要重置 root 密码（`mysqld --initialize-insecure` 或 `--skip-grant-tables`）或由用户提供账号。**这是当前唯一的阻塞项，但不影响"可行性"本身。**
2. **编码问题**：任务书特别强调 GBK vs UTF-8。Python 3 默认 UTF-8，本地 Windows 下读 txt 需显式指定 `encoding='utf-8'`（参考实现数据文件是 UTF-8 无 BOM）；头歌服务器是 Linux/UTF-8，保持一致即可。
3. **输出格式对齐**：ASL、KCN、RMN 及"查找失败""删除成功/失败"等提示语的打印格式必须与头歌评测期望一致，最稳妥做法是照抄 C 参考实现的输出语句。
4. **选做关卡**：19/20 关不完成最高 85 分。Python 下这两关实现成本很低（numpy/scipy 现成），建议全部完成。
5. **GUI 选做**：任务书允许 Qt 或控制台二选一，控制台为必做。Python 可用 `tkinter`（内置）或 PySide6/PyQt6，比 C++ Qt 简单一个量级；建议先用控制台保证必做，有余力再加 GUI。
6. **不要用 SQL 替代手写数据结构**：课程考核核心是数据结构算法本身，SQL 只能作为存储层，否则答辩会被扣分。
